# 项目操作规则

完整历史纠错案例见[归档](archive/20261007-doc-cleanup/files/tasks/lessons.md)；这里只保留可执行规则。

## 规划与记录

- 最新用户指令优先；先读规格、实际 prompt/config/run 和历史教训。仅要求查看时只读；明确授权行动后继续执行。
- 非简单任务先在 [todo.md](todo.md) 写可核对计划并覆盖验证。任务状态只维护在 todo，稳定事实放 [findings.md](../findings.md)，过程证据放实验目录。
- 用户纠正后沉淀通用规则；不要逐次堆积对话历史。精简文档保留当前待办、关键约束和结果入口，先归档原文与 hash；不删实验数据、失败记录或权威报告。 用户指出 todo 过长时，将最新运行入口置顶，已完成与已覆盖计划合并为结果链接；不把旧空复选框当作当前待办，日常只更新主干状态，避免逐轮追加。
- 遵循用户指定 prompt 的文本、范围、语言与长度限制；精简时不把已删除规则换名放回，不擅自补字段、示例或额外阶段。

## 实验与验收

- 新变体使用独立源码/数据/run，保留旧 prompt、缓存和产物；实验简称绑定具体 seed、checkpoint、预测文件与评分版本。
- “完成”须有新鲜验证：适用测试、退出码、完整性、关键计数和来源 hash。区分已启动/已结束、真实接入/可选诊断，不凭文件存在判成功。
- 长训练、推理和 GPU smoke 优先具名 tmux，保存日志/退出码；阶段暂停须阻止下游启动，失败仅恢复失败阶段。
- 优先复用缓存与 conda；依赖冲突用独立环境。模型位置、实际加载、代理子进程环境与显存用真实 smoke 核验，不凭目录名或通用 ping 猜测。
- batch/内核加速须实测并保持有效 batch 和对照条件；复现实验不能顺带引入未确认的工程变量。API 凭据不得进入日志、manifest 或仓库。

## 数据与结论

- TI 看 trigger offset，TC 看 trigger+type，AI/AC 以 TC 成立为条件。错 type 不等于 TI 漏检；type-only 主指标按目标句类型多重集，保留同类事件数量，不能用 TC 替代。
- offset/token/实例评分分开，固定预测集合比较；核验六项 P/R/F1 与实例数。gold 自评不能用来补加模型 F1。
- gold 可用于训练监督、oracle 或探索；推理/检索 query 不依赖待预测 gold。多事件、同类重复、多类型及非名词 nugget 不能静默丢弃。
- 全量分析先用可复用脚本统计，再展示完整例子；明确统计单位、配对与机会分母。候选覆盖不等于最终抽取质量，相关/单 seed 改善不等于因果或稳定收益。

## 当前关键约束

- F.2 以[精确参考](../task/scievents_appendix_f2_exact_reference_v2.md)为准，不能用旧手写 gloss 替代。任务分解与课程设计分开，不默认增加独立 subevent 阶段。
- 主线 prompt、初始化和预算按 run 绑定：AppendixNoCopy 与 UserV2 不混用；Type-CoT warm-start 与原始 Qwen 初始化是不同实验。线上 dev 反馈、事后选 checkpoint 和 dev 反向传播必须区分。
- 检索讨论保留用户已定的 syntax-only、Top1 主配置；理想 gold 示例与实际 query 可用信息分开。
- RE 使用用户最新英文模板；模板 ≤5000 字符，填充后 token 另计。逐关系明确 arg1/arg2 方向，E-* 如需类型则仅去前缀保留后缀；无类型变体不发送 nugget type。当前不输出 confidence/status/ambiguous，不擅自加回 reasoning。
- RE pilot 核查 PART-OF/DEGREE-OF 真实正反向；结构 accepted 不代表语义正确。发现明确反向先停批量、保存原输出，不按 type 静默交换端点；无人工 gold 不报准确率。
- Seed52 复现保持 native micro1×acc16、新初始化及完整 dev 反馈，不引入 batch2/Liger；额外 test 不改变原 dev-best。

- argument列表顺序与论元内部token/offset顺序分开核查：前者通常不影响匹配，但同span不同role字典覆盖敏感；后者被当前canonical排序去重改变，存在可测损失。EC衡量事件间论元-trigger连接，不能解释为完整事件全部论元正确率。

- 用户讨论树输出导致实际test低估时，先回答实际预测在offset与token两种评估链路中的潜在损失；不要转移为argument排列或只讲gold回环。gold回环证明机制，不能替代实际预测中语义/文本正确而转换匹配失分的核查；原token直接比较text优先、否则拼接tokens，不等于语义评分。

- 用户对offset/token链路感到混淆时，用同一真实预测并列原gold、原始树文本和回填位置；区分“比较整棵树”与“解析字段后匹配”。指出独立评分CLI复现官方缺陷并不等于已修复，展示碰撞时标明子集分数。

- 已证实canonical_events对论元offset排序去重会改变原gold词序，这是训练目标构造错误，不只叫评测损失。用户指出时直接承认具体范围；修复应保留原gold tokens及有序offset，区分论元列表排序和片段内部顺序，不能仅修改评分掩盖旧训练目标偏差。

- 树监督验收必须直接比较原始gold的完整事件签名及重复计数；canonical→linearize→parse自洽不足以证明监督正确。片段内部offset不可排序去重；列表位置排序使用min/max，不改变片段词序。修正后另建数据版本并核对仅completion变化，旧run配置和数据保留。

- 用户明确指定层级存在匹配并允许同一文本复用时，不把一对一实例约束当成默认正确指标；按trigger→type→argument→role逐级定义实现。召回与精确率分别统计各侧命中，不用单一TP强行套计数；保存旧结果并明确口径，baseline须用相同新规则重算才能公平比较。

- 用户要求统一EC时，展示列使用EC_C并命名EC，不取EC_I/EC_C平均。论文符合性须核对正式版附录B/C：生成模型明确允许raw text无offset；表6EC要求子事件类型N，而当前/官方代码仅检查子trigger表达存在。不得把实现一致或指标名一致说成完全符合论文定义。

- 不把公平比较笼统表述为所有模型必须使用完全相同的评分程序或重新推理。论文可约定抽取模型用offset、生成模型用token；复用论文结果须注明协议。已有预测可仅重评分；自定义存在匹配与官方token实现的差异须另行说明，不能借论文允许token推定自定义改动也等价。
